# ── Core inference stack ──────────────────────────────────────────────────────
# The LoRA adapters under videos_checkpoints/ and images_checkpoints/ were
# exported by peft 0.19.x. Their adapter_config.json carries fields
# (arrow_config, alora_invocation_tokens, qalora_group_size, ...) that older
# peft releases reject, so do NOT pin peft back below 0.19 — the old
# >=0.10,<0.15 pin cannot load these checkpoints at all.
# torch>=2.1 alone is not a safe floor: 2.1.2 lacks torch.float8_e4m3fnuz,
# which transformers>=4.49 references unconditionally in its internals,
# producing "module 'torch' has no attribute 'float8_e4m3fnuz'" on every
# single model load regardless of which checkpoint. Observed reproducibly
# with torch 2.1.2 + transformers 4.49.0; multiple independent reports
# confirm the attribute exists from torch 2.3 onward. >=2.3 is the real
# floor for this transformers version, not >=2.1.
torch>=2.3
torchvision>=0.18
numpy>=1.26
transformers>=4.45
peft>=0.19
accelerate>=0.26.0
safetensors>=0.4.2
opencv-python>=4.8.0
pillow>=10.0.0

# ── Asynchronous task orchestration (M5) ──────────────────────────────────────
# Celery moves inference off the API process onto worker processes, so several
# uploads are analysed at once instead of serialising behind one event loop,
# and a failed run is retried rather than reported to the user as an error.
# Redis is both the broker and the hot-result cache (app/queue/cache.py).
#
# celery>=5.4 for Python 3.12+/3.13 support: 5.3.x pulls a billiard that fails
# to build there. redis>=5 because app/queue/state.py relies on the client
# exposing zrank/zadd through the same connection pool used for pub/sub.
celery>=5.4
redis>=5.0
